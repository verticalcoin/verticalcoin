## 2026-05-21 - Optimize mempool queries by avoiding unnecessary sorting
**Learning:** `CTxMemPool::queryHashes` and `CTxMemPool::infoAll` were calling `GetSortedDepthAndScore()`, which performs an O(N log N) sort of the entire mempool just to return the list of items to the RPC. Because the callers of these functions don't require the transactions to be sorted by depth and score (in `getrawmempool`, returning it as an array or object dictionary doesn't strictly depend on mining score order, and `infoAll` just iterates through them), this was a massive performance bottleneck when the mempool was large.
**Action:** Replace calls to `GetSortedDepthAndScore()` with direct iteration over `mapTx` (an unordered iteration is O(N) instead of O(N log N)). When the client doesn't explicitly need sorted results, avoid sorting entirely to speed up RPC calls and P2P mempool requests.
